# 10장. 숫자가 말해주지 않는 'Why'를 읽는 법

커머스 상품 구매 리뷰(정성 데이터)를 분석하는 실습 코드입니다. 별점 5점(만족)과 1점(불만)
리뷰가 서로 어떤 단어로 쓰여 있는지를 여러 렌즈로 비교하고, 마지막에 원문 리뷰로 돌아와
확인합니다.

- **실습 1. 전처리와 형태소 분석** — `kiwipiepy`로 체언/용언만 추출
- **실습 2. 텍스트 빈도 분석** — 단어 빈도 표·워드클라우드로 어떤 단어가 많이 나오나
- **실습 3. 텍스트 가중치 분석** — 유니크 키워드(공통어 제거), TF-IDF, 로그 오즈비 z-score로 두 집단을 가르는 단어
- **실습 4. 단어 연관성 및 네트워크 분석** — 바이그램, 동시출현 네트워크 그래프
- **실습 5. 텍스트 주제 및 의미 분석** — 토픽 모델링(LDA), 토픽 시계열
- **실습 6. 원문에 포함된 구체적인 맥락 확인** — KWIC, LDA 토픽별 대표 리뷰 읽기
- **실습 7. 긍정 리뷰가 알려주는 것** — 5점 리뷰의 동시출현에서 미처 몰랐던 쓰임새·고객군 읽기

## 실행 방법

```bash
python generate_data.py                       # 예시 데이터 생성 (data/reviews.csv)
jupyter notebook review_analysis.ipynb        # 노트북을 위에서 아래로 실행 (첫 셀이 의존성 설치)
```

## 파일 구성

| 파일 | 설명 |
| --- | --- |
| `generate_data.py` | 별점별 어휘 차이를 심어 둔 합성 리뷰 생성기 |
| `data/reviews.csv` | 상품 구매 리뷰 (`review_id, product_id, rating, text, created_at`) |
| `review_analysis.ipynb` | 실습 1~7: 전처리→빈도→가중치(변별 키워드)→네트워크→토픽→원문회귀→긍정 리뷰 재발견 노트북 |

> 책 본문의 임베딩 군집화(`sentence-transformers`)·LLM 코딩은 무거운 의존성이나 API 키가
> 필요해 노트북에서는 생략했고, 원문 회귀는 LDA 토픽 비중으로 대표 리뷰를 뽑아 대신했습니다.
