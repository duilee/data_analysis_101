# 유닛 이코노믹스 — CAC·LTV(공헌이익)·회수 곡선

**챕터**: `ROAS가_220인데_왜_우리는_적자예요/` · 노트북: `unit_economics.ipynb`

## 이 방법이 푸는 문제

마케팅 비용·유입·결제라는 원본 로그 세 장으로 "우리 사업이 진짜 돈을 버는가"를 판정한다.
매출(LTR)과 가치(LTV공헌이익)를 구분하고, CAC를 매체비 기준과 fully-loaded 기준으로
나눠 계산한 뒤, 채널 단위로 쪼개고, 코호트별 회수 곡선으로 Payback Period를 실측한다.
"ROAS 220%인데 적자"라는 도입부의 모순이 지표의 '단위'를 맞추는 순간 해소되는 것을
데이터로 재현한다.

## 실행·검증

```bash
python generate_data.py      # data/marketing_costs.csv, users.csv, payments.csv 생성
jupyter nbconvert --to notebook --execute --inplace unit_economics.ipynb
```

- 입력: `data/marketing_costs.csv`(월×채널 비용, 매체비/기타 분리) ·
  `data/users.csv`(유입 명부 — **미결제 유저 포함**) · `data/payments.csv`(결제 건별 매출).
- 흐름: 실습 1 채널별 CAC(매체비 vs fully-loaded, 오가닉은 비용 조인에서 자연 탈락) →
  실습 2 성숙 코호트(획득 후 36개월) 백테스트로 LTR → ×`CM_RATIO`(0.65) → LTV공헌이익 +
  캐스케이드 → 실습 3 CAC·LTV를 채널 단위로 merge(채널 표) → 실습 4 `payback_curve()`로
  회수 곡선 4개(검색·디스플레이 × 2025-03/04) → 실습 5 Payback 기반 CAC 가이드라인.
- **기대 결과**: 생성기가 심은 정답(모두 본문 표의 값)이 복원돼야 한다.
  - 유료 전체 CAC: 매체비 **12,000원** → fully-loaded **14,500원**
  - 채널별 fully-loaded CAC: 검색 11,500 / 디스플레이 5,700 / 리타겟팅 3,600 / 브랜드 28,000원
  - 채널별 LTV공헌이익: 33,000 / 5,900 / 24,000 / 24,000원 (오가닉 26,000원, ±0.2%)
  - 캐스케이드: LTR/매체비 **3.1** → LTV/매체비 **2.0** → LTV/fully-loaded **1.7**
  - LTV:CAC 비율: 2.9 / 1.0 / 6.7 / 0.9 · 유료 전체 1.7
  - 2025-04 검색 코호트 회수 곡선: 월별 공헌이익 403/310/207/110/85/70만원,
    회수율 0.35→1.03 — **6개월째 본전**. 3월 코호트는 7개월째(`QUALITY=0.93`),
    디스플레이는 두 코호트 모두 관측 구간 내 미회수.

아래 1→5 순서로 진행한다. 각 단계 결과를 독자에게 보여주고 확인한 뒤 다음으로 간다.

### 1. 인테이크 — 독자에게 물을 것

- 세 로그의 **파일 경로**와 컬럼 매핑:

| 역할 (노트북 예시명) | 타입 | 의미 | 필수 |
| --- | --- | --- | --- |
| `marketing_costs`: month, channel, media_cost_krw, other_cost_krw | DATE/TEXT/NUM | 월×채널 비용 | 필수* |
| `users`: user_id, channel, signup_date | TEXT/TEXT/DATE | 유입 명부 (미결제 유저 포함) | 필수 |
| `payments`: user_id, payment_date, amount_krw | TEXT/DATE/NUM | 결제 건별 매출 | 필수 |

  *기타 비용(에이전시·제작비 등) 컬럼이 없으면 매체비 기준으로 시작하되, fully-loaded에
  포함할 항목 목록을 합의하고 별도 행/컬럼으로 준비하게 한다.
- **공헌이익률** — 변동비 항목(수수료·판촉·결제/CS·인프라 등)과 매출 대비 비율을 합의해
  `CM_RATIO`를 정한다. 이 값 하나가 모든 LTV·회수 곡선을 좌우한다.
- **'획득'의 기준** — 유입 명부의 한 행이 인스톨인가, 가입인가, 첫 결제인가? CAC 분모와
  LTV 모집단이 같은 기준인지 확인한다(본문 2.2의 단위 맞추기).
- 채널 명명 — 비용 테이블과 유입 테이블의 채널 값이 같은 체계인가? 오가닉의 정의는?
- **데이터 기간** — LTV 실측 지평을 정한다. 3년 치가 없으면 12·24개월 캡으로 명시하고
  시작한다(캡이 다른 LTV끼리 비교 금지).

### 2. 데이터 점검 — 통과 전 분석 시작 금지

```python
duckdb.query("""SELECT (SELECT COUNT(*) FROM read_csv_auto('USERS')) AS users,
    (SELECT COUNT(DISTINCT user_id) FROM read_csv_auto('PAYMENTS')) AS payers,
    (SELECT MIN(signup_date) FROM read_csv_auto('USERS')) AS first_signup,
    (SELECT SUM(CASE WHEN amount_krw <= 0 THEN 1 ELSE 0 END)
       FROM read_csv_auto('PAYMENTS')) AS nonpos_rows""").to_df()
```

- 통과 기준: `payers < users` (결제자만 담긴 명부라면 CAC 분모와 인당 LTV가 모두
  왜곡된다 — 미결제 유저를 포함한 유입 원천을 먼저 확보), 비용·유입 테이블의 채널
  목록 일치, 음수/0원 행(환불) 처리 규칙 합의, LTV 지평만큼 지난 코호트 존재 확인.

### 4. 단계별 진행

1. 채널별 CAC → 어트리뷰션 툴의 채널 리포트와 상식 대조 (매체비/fully-loaded 격차 확인).
2. 성숙 코호트 LTV → 채널별 값 제시, 캐스케이드(매출 기준 vs 공헌이익 기준) 재현.
3. 채널 표 완성 → 평균 비율과 채널별 비율의 격차를 짚는다.
4. 회수 곡선 → 코호트별 Payback 비교. 최근 코호트는 곡선이 '낮은 게 아니라 짧은' 것임을
   함께 확인.
5. CAC 가이드라인 → 목표 Payback은 분석이 아니라 경영 의사결정의 대상임을 안내하고,
   여러 목표값으로 판정이 어떻게 뒤집히는지 보여준다.

### 5. 결과 해석

- 공헌이익 기준 LTV:CAC는 **3:1 이상**이 표준 가이드라인(고정비·추정 오차·재투자 버퍼).
  1:1 언저리는 고정비를 고려하면 사실상 마이너스다.
- 리타겟팅류의 극단적 고효율(예: 6.7)은 라스트 클릭 어트리뷰션의 과대평가를 의심하고
  증분(incrementality) 분석을 권한다.
- blended CAC는 "전사 평균" 질문에, paid CAC는 "이 채널에 더 쓸까" 질문에 쓴다 —
  질문과 CAC의 종류를 맞추는 것이 핵심.

## 함정

- CAC 분모(획득 기준)와 LTV 모집단이 다르면 비율이 통째로 무의미해진다 — 단위 맞추기가
  이 챕터의 제1원칙.
- 결제 로그만 있고 유입 명부가 없는 조직이 많다 — 결제자 기준으로 계산하면 CAC는 커지고
  인당 LTV도 커져서 비율이 우연히 비슷해 보일 수 있지만, 회수 곡선의 절대 수준이 왜곡된다.
- 기간제 선결제(연간권 등)가 섞이면 결제 시점 현금이 아니라 제공 기간에 안분한 매출로
  곡선을 그려야 한다(본문 3.1).
- LTV 실측 지평(예: 36개월 캡)을 명시하지 않으면 지평이 다른 숫자끼리 비교하게 된다.

## 학습 가이드

### 핵심 개념 — 이 챕터를 마치면 설명할 수 있어야 하는 것

- **LTR vs LTV공헌이익** — 매출 합계와, 변동비를 뺀 뒤 실제로 남는 돈의 구분.
  CAC와 비교해야 하는 쪽은 LTV. ROAS는 매출(LTR) 기준의 마케팅 운영 지표일 뿐,
  사업의 수익성 판정 지표가 아니다.
- **fully-loaded CAC** — 매체비에 에이전시·제작비 등까지 얹은 획득 비용. 순익 관리와
  유닛 이코노믹스 계산의 기준.
- **채널 분해** — 평균(유료 전체 1.7)은 어느 채널도 대표하지 못하는 유령 숫자.
- **회수 곡선과 Payback Period** — 예측이 아니라 지나간 코호트의 실측. 누적 공헌이익 ÷
  CAC 총액이 1.0을 넘는 시점.
- **CAC 가이드라인 = 목표 Payback × 유저당 월평균 공헌이익** — 현금흐름까지 고려한
  마케팅 예산 수립. 목표가 바뀌면 채널 판정도 뒤집힌다.

### 개념 체크

1. D7 ROAS가 220%인데 회사 적자 폭이 커지는 것이 왜 가능한가?
   - 힌트: ROAS는 매출(LTR) 기준 — 변동비를 빼고(공헌이익), 비용을 fully-loaded로 넓히고,
     회수의 시차(현금은 오늘 나가고 공헌이익은 수개월에 걸쳐 들어옴)까지 보면 그림이 바뀐다.
2. 유료 전체 LTV:CAC 1.7을 "유령 숫자"라고 부르는 이유는?
   - 힌트: 채널별로 쪼개면 2.9 / 1.0 / 6.7 / 0.9 — 평균은 네 이야기 중 어느 것도 대표하지
     못하고, 채널별 의사결정(증액/중단)에 아무 정보도 주지 않는다.
3. LTV:CAC 3.0에 Payback 18개월인 서비스와, 2.0에 6개월인 서비스 — 어느 쪽이 더 빨리
   성장할 수 있고 왜인가?
   - 힌트: 같은 예산의 회전 속도. 회수가 빠르면 1년에 같은 돈을 두 번 굴린다 — 유닛이
     흑자여도 회수가 느리면 흑자 도산이 가능하다.
