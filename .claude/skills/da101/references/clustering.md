# 사용패턴 클러스터링 — KMeans 페르소나

**챕터**: `08_Machine_Learning으로_찾아보는_유저들의_사용패턴/` · 노트북: `user_segmentation.ipynb`
**동기화**: 코드 기준 커밋 `758ccde` (2026-09-13) — 노트북·README·sql과 대조 완료. 책 본문 대조는 미실시.

## 이 방법이 푸는 문제

유저의 행동 피처를 KMeans로 비지도 군집화해 사용 패턴(페르소나)을 발견하고,
중심점(centroid)을 원단위로 복원해 해석·네이밍한 뒤, 클러스터별 리텐션 KPI와 연결해
액션으로 잇는다. 흐름: 피처 SQL → 분포 확인 → StandardScaler → k 선택(Elbow·Silhouette) →
클러스터링·centroid 해석 → PCA 시각화 → 신규/기존 비교 → 클러스터별 리텐션 → 라벨 적재·모델 저장.

## 실행·검증

```bash
python generate_data.py      # data/alarm_daily.csv, data/user_master.csv 생성
jupyter nbconvert --to notebook --execute --inplace user_segmentation.ipynb
```

- 입력: `alarm_daily.csv`(일별 알람 사용 피처), `user_master.csv`(`user_id, new_flag, retained_d7`).
- 실습 0은 두 셀이다: `con.execute` 셀이 `clip(x, lim, cap)` 매크로와 주중 필터
  (`isodow(...) BETWEEN 1 AND 5`)의 `daily_stat` 뷰를 등록하고, `query` 셀이 기간 평균·클리핑으로
  유저 피처 7종 + 클리핑판 `*_cluster` 7종을 만든다(`sql/extract_features.sql`은 두 셀의 합본).
- **기대 결과**: 생성기가 4개 페르소나를 심었다 — `minimalist`(1,389명), `trying_maximalist`
  (600명), `weak_maximalist`(312명), `weak_minimalist`(99명), 총 2,400명. `k = 4`에서 KMeans가
  이 구성을 거의 그대로 복원하고, centroid의 알람 개수·인터벌·기상 소요시간이 심어둔 특성과
  일치해야 한다.
- **주의**: 실행하면 `output/user_labels.csv`, `models/*.pkl`이 생성된다(gitignore 대상).
  알람 시각 피처는 분 단위 정수(0~1439)다.

## 내 데이터에 적용 — 인터랙티브 프로토콜

아래 1→5 순서로 진행한다. 각 단계 결과를 독자에게 보여주고 확인한 뒤 다음으로 간다.
이 노트북에는 `[내 데이터 적용]` 주석이 없고, **피처 SQL 전체가 도메인 특화**라 8개 챕터 중
치환 범위가 가장 넓다 — 피처 설계 단계에 시간을 들인다.

### 1. 인테이크 — 독자에게 물을 것

- 유저 행동 로그(일별 집계 가능한 형태)의 **파일 경로**는?

| 역할 (노트북 예시명) | 의미 | 필수 |
| --- | --- | --- |
| 행동 로그 (`alarm_daily.csv`) | 유저×일 단위 행동 지표들 | 필수 |
| 유저 마스터 (`user_master.csv`) | `user_id`, 그룹 축(예: `new_flag`), 성과 라벨(예: `retained_d7`) | 그룹 비교·KPI 연결 시 필수 |

- **패턴을 가를 것 같은 행동 지표 5~8개**는? (사용 빈도, 시간대, 기능 사용 비율, 세션 길이 등 —
  독자의 도메인 지식으로 고르게 한다. 이 선택이 결과의 절반이다.)
- 각 지표의 이상치 상한(클리핑 기준)을 어디에 둘지? (노트북 예: `clip(scheduled_cnt, 10, 11)`,
  `clip(avg_interval, 60, 65)` — 상한 초과분을 대체값으로)
- 주중/주말 등 **관측 조건 필터**가 필요한가? (노트북은 주중만 사용)
- 클러스터와 연결할 성과 지표는? (D7 리텐션, 결제 여부 등)

### 2. 데이터 점검 — 통과 전 분석 시작 금지

- 유저 수 확인 (수백 명 미만이면 클러스터가 불안정함을 경고), 피처별 null·분산 확인
  (분산이 0에 가까운 피처는 제외 제안), 피처 간 상관 행렬 → 상관 0.9+ 쌍이 있으면 한쪽 제거를
  제안한다(그 축이 과대 대표되므로).

### 3. 코드 치환 지도

| 앵커 (실습/식별자) | 무엇을 | 어떻게 |
| --- | --- | --- |
| 실습 0 `con.execute` 셀 | `alarm_daily.csv` 경로, 주중 필터 `isodow(...) BETWEEN 1 AND 5`, `daily_stat` 뷰의 일별 지표 | 독자 지표로 재작성. 구조(일별 `daily_stat` → 유저 `user_features`)는 유지 |
| 실습 0 `query` 셀 | `user_master.csv` 경로, `user_features` CTE, `clip(값, 상한, 대체값)` 호출 7개 | 인테이크에서 정한 임계값으로. 클리핑판 `*_cluster` 쌍 생성 규칙은 유지 |
| 실습 1 | `feat_cols` 리스트 (7개 피처명), `plt.subplots(2, 4)`·`axes.ravel()[-1].set_visible(False)`(7개 전제) | 독자 피처명으로 — 피처 수가 다르면 그리드도 조정 |
| 실습 2 | `cluster_cols` (`endswith('_cluster')`) | 명명 규칙 유지하면 자동 |
| ⚠ 실습 3 | `k = 4` **와 `fit_kmeans(frame, k=4)` 시그니처 기본값 두 곳** — 실습 5는 `fit_kmeans(df_new)`처럼 k를 넘기지 않아 기본값을 쓴다 | Elbow·Silhouette 결과 보고 결정 (아래 4단계). 두 곳 함께 바꾸거나 실습 5 호출에 `k=k`를 넘길 것 |
| 실습 3 `KOR` 딕셔너리 | 한국어 헤더 맵 7개 키 — `summary[list(KOR.values())]`로 인덱싱하므로 키가 피처명과 안 맞으면 KeyError | 독자 피처명으로 재작성 |
| 〃 | `PERSONA_ORDER`, `name_persona(r)`의 컷오프 (`scheduled_cnt < 2` 등) | 독자 centroid를 보고 새로 작성 — 예시 도메인 전용이므로 그대로 쓰면 안 됨 |
| 실습 5·6 | `new_flag` 그룹 축, `retained_d7` KPI 컬럼 | 독자 컬럼으로 |
| 실습 7 | `output/`·`models/` 경로 | 필요 시 변경 |

- `fit_kmeans(frame, k=4)`, `random_state=42, n_init=10`, scaler→`inverse_transform` 흐름은
  그대로 재사용한다.

### 4. 단계별 진행

1. 피처 SQL 실행 → 피처 요약 통계·히스토그램. 변별력 없는 피처는 여기서 빼고 다시.
2. 스케일링 → Elbow(`k_values = range(1, 11)`)·Silhouette(`range(2, 11)`) 플롯 제시 →
   **독자와 함께 k 결정** (기준: 곡선 + "centroid를 사람 말로 네이밍할 수 있는가").
3. KMeans 적합 → `inverse_transform`으로 원단위 centroid 표 제시 → 독자와 페르소나 네이밍.
   네이밍 안 되는 클러스터가 있으면 k 또는 피처를 조정하고 2로 돌아간다.
4. PCA 시각화로 분리도 확인.
5. (그룹 축이 있으면) 신규/기존 분리 클러스터링 비교 → 클러스터×성과 지표 조인 →
   "어느 페르소나가 위험한가" 액션 논의.
6. 라벨 CSV·pickle 저장 — 운영 적용 시 분포 변화(계절·제품 변경)에 따른 재학습 필요를 안내.

### 5. 결과 해석

- centroid는 반드시 원단위로 읽는다. 페르소나 이름은 행동 서술("알람 많고 못 일어나는")로.
- 클러스터별 성과 차이는 **상관**이다 — "이 행동을 시키면 성과가 오른다"는 실험으로 확인.

## 함정

- KMeans는 어떤 데이터든 k개로 나눠 준다 — 클러스터가 나왔다고 패턴이 실재한다는 뜻이
  아니다. Silhouette이 낮고 네이밍이 안 되면 "패턴 없음"이 정답일 수 있다.
- 스케일링 없이 돌리면 단위가 큰 피처가 거리를 지배한다.
- 상관 높은 피처 쌍은 그 축을 과대 대표시킨다.

## 학습 가이드

### 핵심 개념 — 이 챕터를 마치면 설명할 수 있어야 하는 것

- **비지도 군집화** — 라벨 없이 거리 기반으로 비슷한 유저를 묶는 것. 정답이 없으므로 해석
  가능성이 품질 기준이 된다.
- **표준화(StandardScaler)** — 피처를 평균 0·분산 1로 맞춰 거리 계산에서 단위 영향을 제거.
- **Elbow / Silhouette** — 관성 감소 꺾임 / 응집·분리도 점수로 k를 고르는 두 보조 지표.
- **centroid 해석** — `inverse_transform`으로 원단위 복원한 중심점을 읽어 클러스터에 의미를
  부여하는 단계. 여기가 ML이 아니라 도메인 지식의 영역.
- **클리핑** — 이상치가 거리(따라서 centroid)를 왜곡하지 않도록 상한을 두는 전처리.

### 개념 체크

1. 스케일링 없이 KMeans를 돌리면 어떤 피처가 결과를 지배하는가? 이 챕터 데이터로 예를 들면?
   - 힌트: 값 범위가 큰 피처 — 분 단위 `avg_interval`(0~수십)이 개수 피처(0~3)를 압도한다.
2. Elbow가 뚜렷하지 않을 때 k를 정하는 실무적 기준은?
   - 힌트: Silhouette 보조 + "모든 centroid가 사람 말로 네이밍되는 최대 k".
3. "클러스터별 리텐션이 다르다"에서 "이 행동을 시키면 리텐션이 오른다"로 바로 가면 안 되는
   이유는?
   - 힌트: 자기선택 — 원래 잔존 성향이 높은 유저가 그 행동을 하는 것일 수 있다. 실험 필요.
