## 이 방법이 푸는 문제

유저의 행동 피처를 KMeans로 비지도 군집화해 사용 패턴(페르소나)을 발견하고,
중심점(centroid)을 원단위로 복원해 해석·네이밍한 뒤, 클러스터별 리텐션 KPI와 연결해
액션으로 잇는다. 흐름: 피처 SQL → 분포 확인 → StandardScaler → k 선택(Elbow·Silhouette) →
클러스터링·centroid 해석 → PCA 시각화 → 신규/기존 비교 → 클러스터별 리텐션 → 라벨 적재·모델 저장.

**책 이론부 포인터** (자세한 설명은 책에서 읽게 안내한다)

- 8.1 — "평균 유저"는 존재하지 않는다: 평균(알람 3개·기상 15분)이 어느 그룹도 대변하지 못한 사례. 1장의
  활동성 축(라이트/헤비)만으로는 "어떻게" 쓰는지 안 보이므로 행동 패턴 단위 구분이 필요. 세그먼트가 있으면
  같은 구독 전환 목표라도 그룹별 소구점(한 번에 일어나기 / 기분 좋게 일어나기 / 아침 시간 활용)을 다르게
  잡을 수 있다. 세그먼트는 정답이 아니라 팀 논의의 시작점.
- 8.2 — 피처 엔지니어링. 8.2.1 도메인 지식 반영(표면 피처 → 기상 소요시간·인터벌처럼 한 단계 깊은 피처,
  주중/주말 분리·기간 평균으로 노이즈 완화), 8.2.2 변별력 검증(`.describe()`·`.hist()` EDA, 이상치 정제,
  스케일 차이 → 표준화/정규화). 책 그림 8.1.
- 8.3 — 왜 클러스터링인가(라벨 편향 없이 다차원 조합), KMeans 직관. 8.3.1 k 정하기: Elbow(Inertia 감소가
  완만해지는 꺾임)·Silhouette(-1~1, 응집·분리도) — 둘 다 가이드일 뿐, k는 "팀이 해석·관리할 수 있는
  개수"로 판단(책은 4로 고정). 앤드류 응의 "k에 정답은 없다" + 티셔츠 사이즈 S/M/L vs XS~XL 비유(만족도 vs
  관리 비용 트레이드오프). 책 그림 8.2. 코드는 [8.5.3](Elbow·Silhouette), PCA 시각화는 [8.5.4.2]로 안내.
  8.3.2 centroid = 피처 평균으로 만든 가상의 대표 유저, `.cluster_centers_`를 요약표로(책 표 8.1 — 실서비스
  규모 예시로 노트북 숫자와 다르다, 아래 기대 결과 참고). 8.3.3 페르소나 네이밍 — 숫자 요약보다 이름이
  전달력이 강함(책 표 8.2). 네이밍 전 액션 예시: 클러스터 0(해제까지 오래) → 알람 추가 설정 유도, 클러스터 2
  (알람 많은데 못 일어남) → 강력한 기상 미션·유료 기능 넛지. 작명이 어려우면 PM·디자이너와 함께.
- 8.4 — 확장: 기존 코호트(신규/기존·국가) 안에서 재클러스터링, 신규→기존 세그먼트 이동 추적, 클러스터×KPI
  연결(리텐션 높은 그룹을 시드로 확장), 인과 단정 금지 → A/B 테스트, 모델(`.pkl`)·라벨 저장으로 이력 관리.
- 정리하며 — 질문 "유저가 '어떻게' 쓰는지 유형(페르소나)으로 나눌 수 있나" / 해결 = 피처 설계 → 표준화 →
  KMeans(Elbow·Silhouette) → 중심점 해석 → 핵심 지표 연결 / 주의 = KMeans는 패턴 없어도 k개로 나눔, 피처
  선택이 결과 좌우, 인과 보장 없음 / 다음 액션 = 모델·scaler 저장해 라벨 지표화 + 리텐션 높은 클러스터를
  넓히는 실험 설계. 페르소나 네이밍은 결과를 팀이 "먹기 좋게" 포장하는 일 — 공감 없이는 액션이 안 된다.

```bash
  --output-dir ../../my-work/08_Machine_Learning으로_찾아보는_유저들의_사용패턴   # 결과는 my-work에
```

- 입력: `alarm_daily.csv`(일별 알람 사용 피처), `user_master.csv`(`user_id, new_flag, retained_d7`).

  이 구성을 거의 그대로 복원하고, centroid의 알람 개수·인터벌·기상 소요시간이 심어둔 특성과

  인원·소수점은 다르다. 책 실습 절에 실린 결과(노트북 출력과 동일):

  - 8.5.4.1 요약표 — 0 의지박약 미니멀리스트(알람 1.40, 인터벌 8.58분, 해제까지 68.09분, 첫 알람~해제
    75.15분, 99명 4.12%), 1 미니멀리스트(1.19 / 3.14 / 6.21 / 8.41, 1,390명 57.92%), 2 의지박약

## 내 데이터에 적용 — 인터랙티브 프로토콜

아래 1→5 순서로 진행한다. 각 단계 결과를 독자에게 보여주고 확인한 뒤 다음으로 간다.
이 노트북에는 `[내 데이터 적용]` 주석이 없고, **피처 SQL 전체가 도메인 특화**라 책의 장 중
치환 범위가 가장 넓다 — 피처 설계 단계에 시간을 들인다.

### 1. 인테이크 — 독자에게 물을 것

- 유저 행동 로그(일별 집계 가능한 형태)의 **파일 경로**는?

| 역할 (노트북 예시명) | 의미 | 필수 |
| --- | --- | --- |
| 행동 로그 (`alarm_daily.csv`) | 유저×일 단위 행동 지표들 | 필수 |
| 유저 마스터 (`user_master.csv`) | `user_id`, 그룹 축(예: `new_flag`), 성과 라벨(예: `retained_d7`) | 그룹 비교·KPI 연결 시 필수 |

- **패턴을 가를 것 같은 행동 지표 5~8개**는? (사용 빈도, 시간대, 기능 사용 비율, 세션 길이 등 —
  독자의 도메인 지식으로 고르게 한다. 이 선택이 결과의 절반이다.)
- 각 지표의 이상치 상한(클리핑 기준)을 어디에 둘지? (노트북 예: `clip(scheduled_cnt, 10, 11)`,
  `clip(avg_interval, 60, 65)` — 상한 초과분을 대체값으로)
- 주중/주말 등 **관측 조건 필터**가 필요한가? (노트북은 주중만 사용)
- 클러스터와 연결할 성과 지표는? (D7 리텐션, 결제 여부 등)

### 2. 데이터 점검 — 통과 전 분석 시작 금지

- 유저 수 확인 (수백 명 미만이면 클러스터가 불안정함을 경고), 피처별 null·분산 확인
  (분산이 0에 가까운 피처는 제외 제안), 피처 간 상관 행렬 → 상관 0.9+ 쌍이 있으면 한쪽 제거를
  제안한다(그 축이 과대 대표되므로).

- `fit_kmeans(frame, k=4)`, `random_state=42, n_init=10`, scaler→`inverse_transform` 흐름은
  그대로 재사용한다.

### 4. 단계별 진행

1. 피처 SQL 실행 → 피처 요약 통계·히스토그램. 변별력 없는 피처는 여기서 빼고 다시.
2. 스케일링 → Elbow(`k_values = range(1, 11)`)·Silhouette(`range(2, 11)`) 플롯 제시 →
   **독자와 함께 k 결정** (기준: 곡선 + "팀이 해석·관리할 수 있는 개수" + "centroid를 사람 말로
   네이밍할 수 있는가").
3. KMeans 적합 → `inverse_transform`으로 원단위 centroid 표 제시 → 독자와 페르소나 네이밍.
   네이밍 안 되는 클러스터가 있으면 k 또는 피처를 조정하고 2로 돌아간다.
4. PCA 시각화로 분리도 확인.
5. (그룹 축이 있으면) 신규/기존 분리 클러스터링 비교 → 클러스터×성과 지표 조인 →
   "어느 페르소나가 위험한가" 액션 논의.
6. 라벨 CSV·pickle 저장 — 운영 적용 시 분포 변화(계절·제품 변경)에 따른 재학습 필요를 안내.

### 5. 결과 해석

- centroid는 반드시 원단위로 읽는다. 페르소나 이름은 행동 서술("알람 많고 못 일어나는")로.
- 액션으로 번역(책 8.3.3·정리하며): 페르소나별로 다른 처방을 붙인다 — 알람 적은데 오래 걸리는 그룹은 알람
  추가 유도, 알람 많은데 못 일어나는 그룹은 강한 미션·유료 기능 넛지. 성과(리텐션) 높은 클러스터는 시드로
  삼아 넓히는 실험을 설계하고, 낮은 클러스터가 "위험한 그룹"이다.
- 클러스터별 성과 차이는 **상관**이다 — "이 행동을 시키면 성과가 오른다"는 실험으로 확인.
- 유의미하다고 판단되면 모델·scaler·라벨을 저장해 이후 같은 기준으로 유저 패턴을 지표화한다(책 8.4).

## 함정

- KMeans는 어떤 데이터든 k개로 나눠 준다 — 클러스터가 나왔다고 패턴이 실재한다는 뜻이
  아니다. Silhouette이 낮고 네이밍이 안 되면 "패턴 없음"이 정답일 수 있다. 클러스터별 핵심 지표
  (리텐션 등)가 실제로 갈리는지까지 봐야 "유효한 세그먼트"다(책 8.3).
- "평균 유저"의 함정 — 전체 평균은 어느 그룹도 대변하지 못할 수 있다. 세그먼트로 나눠 보는 이유가
  이것이다(책 8.1).
- 피처 선택이 결과를 좌우한다 — 표준 피처 플레이북은 없다. 모두 비슷한 값을 갖는 피처(변별력 없음)는
  빼고, 도메인 맥락을 한 단계 더 입힌 피처를 찾는다(책 8.2).
- 스케일링 없이 돌리면 단위가 큰 피처가 거리를 지배한다.
- 상관 높은 피처 쌍은 그 축을 과대 대표시킨다.
- k는 계산이 아니라 판단이다 — Inertia가 더 낮아도 팀이 이해·관리 못 하는 개수면 줄인다(책 8.3.1).
- 리텐션 높은 클러스터의 행동이 리텐션의 원인이라 단정하지 않는다 — 가설로 세워 A/B 테스트로
  검증(책 8.4). 세그먼트는 정답이 아니라 팀 논의의 시작점.
- KMeans 라벨 번호는 모델마다 임의다(책 8.5.5.1·8.5.5.3) — 신규/기존 모델의 같은 0번이 다른 패턴일 수 있으니
  centroid 값으로 맞추고, 라벨을 저장할 때 어느 모델인지(`new_flag`)를 함께 남긴다.
- 모델만 저장하면 표준화 기준이 사라진다(책 8.5.5.3) — 새 데이터를 같은 라벨 기준으로 매기려면 학습에 쓴
  `StandardScaler`를 모델과 함께 pickle 한다.

## 학습 가이드

### 핵심 개념 — 이 장을 마치면 설명할 수 있어야 하는 것

- **비지도 군집화** — 라벨 없이 거리 기반으로 비슷한 유저를 묶는 것. 정답이 없으므로 해석
  가능성이 품질 기준이 된다.
- **표준화(StandardScaler)** — 피처를 평균 0·분산 1로 맞춰 거리 계산에서 단위 영향을 제거.
- **Elbow / Silhouette** — 관성 감소 꺾임 / 응집·분리도 점수로 k를 고르는 두 보조 지표.
- **centroid 해석** — `inverse_transform`으로 원단위 복원한 중심점을 읽어 클러스터에 의미를
  부여하는 단계. 여기가 ML이 아니라 도메인 지식의 영역.
- **클리핑** — 이상치가 거리(따라서 centroid)를 왜곡하지 않도록 상한을 두는 전처리.

### 개념 체크

출제 범위는 위 핵심 개념 5가지(비지도 군집화·표준화·Elbow/Silhouette·centroid 해석·클리핑).

1. 스케일링 없이 KMeans를 돌리면 어떤 피처가 결과를 지배하게 될까요? 이 장의 예시 데이터로 예를
   들어 설명해 보세요.
   - 힌트: 값 범위가 큰 피처 — 분 단위 기상 시간 `first_ring_to_last_dismiss`(0~120분)가 비율 피처
     `avg_snooze`(0~1대)나 개수 피처(`scheduled_cnt`, 1~3)를 압도해 사실상 한 피처로만 군집화된다.
     표준화는 모든 피처를 "평균에서 얼마나 벗어났나"라는 같은 저울로 바꾼다.
2. Elbow 곡선의 꺾임이 뚜렷하지 않을 때, k를 정하는 실무적인 기준은 뭘까요?
   - 힌트: Silhouette 보조 + "팀이 실제로 해석·관리할 수 있는 개수" + "모든 centroid가 사람 말로
     네이밍되는 최대 k". Inertia가 더 낮다고 k를 늘리지 않는다.
3. 중심점(centroid)은 무엇이고, 왜 `scaler.inverse_transform`으로 되돌린 뒤 읽어야 할까요?
   - 힌트: 클러스터에 속한 유저들의 피처 평균으로 만든 "가상의 대표 유저". 표준화 공간의 값은
     "평균에서 몇 σ"라 사람이 읽을 수 없으니 분·개수 단위로 복원해야 네이밍이 가능하다.
4. 8.5.2.1에서 클러스터 입력에는 클리핑한 `*_cluster` 컬럼을 쓰고 원본 피처도 따로 남겨 둔 이유는?
   - 힌트: 극단값 유저 몇 명이 거리 계산과 centroid를 끌고 가 그룹 경계를 흐리므로 클러스터링에는
     클리핑판을, 분포 확인·해석에는 원본을 쓴다.
5. "클러스터별 리텐션이 다르다"에서 "이 행동을 시키면 리텐션이 오른다"로 바로 가면 안 되는
   이유는?
   - 힌트: 자기선택 — 원래 잔존 성향이 높은 유저가 그 행동을 하는 것일 수 있다. 가설로 세워 A/B
     테스트로 검증. KMeans는 라벨(리텐션)을 입력으로 쓰지 않았다는 점도 함께.
