## 이 방법이 푸는 문제

고정 분할 A/B 테스트는 실험 기간 내내 열등한 안에도 트래픽을 쓴다. Multi-Armed Bandit의
**Thompson Sampling**(Beta-Bernoulli 베이지안)은 성과가 좋아 보이는 안에 트래픽을 점점
몰아주면서도 탐색을 유지해, 실험 비용(누적 regret)을 줄인다. 배너·문구·추천 슬롯처럼
"빨리 좋은 안으로 수렴하면 되는" 최적화에 맞는 도구다.

## 실행·검증

```bash
jupyter nbconvert --to notebook --execute --inplace mab_thompson_sampling.ipynb
```

- **이 챕터는 데이터 파일·생성기·SQL이 없다.** 배너의 '진짜 확률'을 코드에 정해 두고
  노트북이 직접 시뮬레이션한다(`np.random.seed(42)`). `generate_data.py` 단계를 건너뛴다.
- **기대 결과** (실습별 심어둔 정답):
  - 실습 1: `BANNER_PROBABILITIES = [0.2, 0.5, 0.75]`, `NUM_TRIALS = 2000` — Beta 분포가
    좁아지며 0.75 슬롯에 노출 집중 (`checkpoints` 시점별 패널로 관찰).
  - 실습 2: `PROBS = [0.05, 0.07, 0.01]` — `run_ab` 대비 `run_ts`의 누적 regret이 확연히 낮다.
  - 실습 3: `CTR = [0.009, 0.006, 0.003]`, `IMPR = 1000` — 그냥 보면 Beta 분포가 겹치고,
    `make_beta(coef)`/`exposure_share(15)`의 계수 적용으로 분리가 빨라진다.
  - 실습 4: `SCHED`(i=1000에서 최적 arm이 뒤집힘) — 실습 2의 `run_ts`를 재사용해
    `run_ts(SCHED, N4, gamma=0.9)`(`decay_every`는 기본값 50)로 돌린 Discounted TS가 일반 TS와
    달리 새 최적 arm으로 갈아탄다.

## 내 데이터에 적용 — 인터랙티브 프로토콜

이 챕터의 "적용"은 두 갈래다: **(A) 시뮬레이션으로 자기 상황 사전 검증**, **(B) 실제 노출·클릭
로그를 prior로 연결**. 아래 1→5 순서로 진행하고, 각 단계 결과를 독자와 확인한다.

### 1. 인테이크 — 독자에게 물을 것

- 최적화 대상은? (배너/문구/추천 슬롯 등) **arm 수**는?
- 보상 정의는? — 즉시 관측되는 이진 지표(클릭 등)인가? 지연 지표(가입 후 잔존)라면 이
  방법을 그대로 쓰면 안 됨을 먼저 안내한다 (함정 참고).
- 예상 CTR 수준과 arm 간 차이는? (예: 1% vs 0.8% — 낮고 가까울수록 필요 트래픽 급증)
- **일 트래픽**(노출 수)은?
- 최적 arm이 시간에 따라 바뀔 요인(시즈널리티, 소재 피로도)이 있는가?
- (B 경로) 운영 중인 안별 **누적 노출 수·클릭 수** 로그가 있는가? arm별 귀속(어트리뷰션)은
  정확한가?

### 2. 데이터 점검 — 시뮬레이션 설계 검증

- (A) 인테이크 값으로 시뮬레이션 파라미터 표를 만들어 독자와 확인: arm 수, 확률 배열,
  trial 수(= 일 트래픽 × 예상 운영일).
- (B) 노출·클릭 로그라면: arm별 노출 ≥ 수백, 클릭 ≥ 1 확인. 0클릭 arm은 prior가 균등에
  가까워 탐색이 오래 걸림을 안내.

### 4. 단계별 진행

1. 독자 시나리오로 실습 1 구조를 돌려 수렴 시점을 확인 → "우리 트래픽으로 약 며칠"로 번역.
2. 실습 2 구조로 AB 대비 누적 regret 차이 → "AB로 했으면 클릭 몇 개를 버렸다"로 번역.
3. CTR이 낮고 가까우면 실습 3의 계수 실험 → 계수별 `exposure_share` 비교로 적정 계수 선택.
4. 변화 요인이 있으면 실습 4 구조로 gamma·decay_every 튜닝.
5. (B 경로) 실데이터 prior로 현재 시점의 Beta 분포를 그려 "지금 당장 트래픽을 어떻게 나눠야
   하는지" 노출 비중 권고안을 만든다.

### 5. 결과 해석

- 시뮬레이션 결론은 "이 설정이면 N일 안에 수렴, AB 대비 regret M 절약" 형태로 정리한다.
- 수렴 후에도 탐색이 완전히 0이 되지는 않음(불확실성 유지)을 설명한다.

## 함정

- MAB는 "왜 이겼는지"를 알려주지 않는다 — 효과 크기 추정·인과 해석이 목적이면 A/B 테스트를
  쓴다. MAB는 수렴이 목적일 때 쓴다.
- 보상이 즉시 관측되지 않는 지표(D7 잔존 등)에 그대로 쓰면 피드백 지연으로 수렴이 왜곡된다.
  즉시 관측되는 대리 지표(클릭)에 적합하다.
- 노출-클릭 로그의 arm별 귀속(어트리뷰션)이 정확하다는 전제가 필요하다.

## 학습 가이드

### 핵심 개념 — 이 챕터를 마치면 설명할 수 있어야 하는 것

- **탐색-활용 트레이드오프** — 더 알아보기(탐색) vs 아는 최선 쓰기(활용)의 균형 문제.
  MAB 알고리즘은 이 균형의 자동화다.
- **Beta-Bernoulli 켤레** — 클릭/비클릭(Bernoulli) 관측이 쌓일 때 Beta(성공+α, 실패+β)로
  사후분포가 닫힌 형태로 갱신되는 구조. `Banner.update()` 한 줄이 그것.
- **Thompson Sampling** — 각 arm의 사후분포에서 **한 번씩 샘플**해 가장 큰 arm을 노출.
  불확실한 arm은 가끔 크게 샘플되어 자연스럽게 탐색된다.
- **누적 regret** — "최적 arm만 노출했을 때 대비 잃은 보상"의 누적. 알고리즘 비용의 단위.
- **비정상(non-stationary) 환경** — 진짜 확률이 시간에 따라 변하는 환경. 과거 데이터를
  할인(discount)해야 적응할 수 있다.

### 개념 체크

1. Thompson Sampling에서 "샘플링"하는 대상은 무엇이고, 그것이 탐색-활용 균형을 어떻게
   자동으로 만드는가?
   - 힌트: 사후분포에서 1개 샘플 — 분포가 넓은(불확실한) arm은 가끔 최댓값이 되어 노출 기회를
     얻고, 좁아지면 자연히 줄어든다.
2. 누적 regret이란 무엇이며, AB 테스트의 regret이 직선으로 증가하는 이유는?
   - 힌트: AB는 끝까지 고정 비율로 열등 arm에 노출 → 매 trial 일정량의 손실이 쌓인다.
3. 어떤 의사결정에는 MAB 대신 A/B 테스트를 써야 하는가?
   - 힌트: 효과 크기·신뢰구간이 필요한 결정(가격 변경, 대규모 개편) — MAB는 트래픽을
     몰아주므로 열등 arm의 추정이 부정확해진다.

### 심화 과제

   예측하게 한다 → 수정 → 재실행 → regret 곡선 대조. (간격 Δ가 절반이면 필요 표본 ≈ 4배라는
   감각이 목표.) 끝나면 원래 값 복원.
