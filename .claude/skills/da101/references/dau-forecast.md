## 이 방법이 푸는 문제

신규 유저 리텐션 커브에 멱함수(power law) `y = a·x^b`를 적합해 모양 계수 `b`를 구하고,
`x^b`의 1년 누적합을 상수 하나로 접어 **`DAU 기여 = 신규 유저 수 × D1 리텐션 × 상수`**
공식을 만든다. 기능 하나·유입 캠페인 하나가 장기적으로 DAU 몇 명짜리인지 어림할 수 있다.

**책 이론부 포인터** (자세한 설명은 책에서 읽게 안내한다)

- **도입 퀴즈 (1절)** — 일 신규 6,700명·D1 7%인 기능 A와 일 신규 600명·D1 35%인 기능 B 중
  어느 쪽이 더 큰 DAU로 수렴하는가. 답은 실습 3에서 공개된다(A ≈ 29,500, B ≈ 13,200 — 상수 63 기준).
- **왜 이 지표 쌍인가 (2·3절)** — 신규 기능의 임팩트를 셈하려면 레버(유입·리텐션)가 DAU를 얼마나
  움직이는지와, 그 지표가 피드백 주기가 짧은 선행지표인지를 함께 봐야 한다. 신규 유저 수와 신규
  D1 리텐션은 둘 다 만족하고 팀 누구나 이해하는 한 쌍이다. 책 3절 참고.
- **Carrying Capacity의 실패 (4절)** — `신규 / 일별 이탈률`은 매일 같은 비율로 남는다는 등비급수(지수
  감쇠) 가정 위에 있어, 기능 A를 7,200명으로 계산하지만 실제는 2만이 넘는다. 활성 유저를 '와우 모먼트
  경험자'로 좁게 정의하고 80~90% 일간 리텐션을 전제한 공식이라 일반 DAU에 맞지 않는다. 책 4절 참고.
- **멱함수 커브와 누적합 (5절)** — 실제 신규 리텐션은 초반 급락 후 완만해지므로 `y = a·x^b`(b<0)가 맞는다.
  `a`는 시작점, `b`는 모양. 오늘 DAU = 과거 코호트 잔존의 합 = `신규 유저 수 × 리텐션 커브 누적합`
  (일별 신규가 일정하다는 가정). 이 누적합은 4장 Lifetime(커브 아래 면적)과 같은 개념. 책 5절 참고.
- **딸깍 공식 (6절)** — 누적합을 `1 + a·(1^b + … + N^b)`로 분해하면 `a`가 곧 신규 D1 리텐션이고,
  괄호 안은 `b`만 알면 미리 계산해 둘 상수다. `b`는 신규 기능이 아니라 **서비스 전체 신규 유저**의
  커브(또는 가장 유사한 기능의 커브)에서 구한다 — 기능별 데이터를 1~2달 기다리는 것은 선제 예측이라는
  목적에 맞지 않는다. 책 6절 참고.
- **의사결정 도구로 (7절)** — 상수 63 가정 시 기능 A 시나리오: 기준 ≈29,500 / 신규 +50% ≈44,300 /
  D1 +5%p ≈50,600 / 신규 +20%·D1 +2%p ≈45,600. 레버 환산: D1 1%p ≈ DAU 4,200 ≈ 일 신규 1,000명.
  단, 이건 **기능 DAU**이지 서비스 전체 DAU의 순증이 아니다(다른 기능에서 옮겨 온 유저일 수 있음) —
  순증은 실험군/대조군으로 재라고 권한다. 책 7절 참고.
- **정리하며** — 실전 팁 둘: 오픈 효과·배포율로 흔들리는 초반 수치 대신 안정화된 수치를 쓸 것,
  오래된 기능은 이미 쌓인 유저를 `+ 기존 유저 계수`로 더할 것.

### 4. 단계별 진행

1. CREATE VIEW 셀 → `query` 셀 순으로 실행 → 리텐션 테이블 출력. day_diff별로 단조 감소하는지,

   빠져 `curve_fit`이 길이 불일치로 실패한다 — 부족하면 `reindex(days, fill_value=0)`).
2. 그룹별 `curve_fit` → `df_constant`(그룹별 `a`, `b`) 표 제시. 그룹 간 `b` 편차 확인 —
   편차가 크면(예: 0.1 이상) 상수를 하나로 접지 말고 세그먼트별 상수를 제안.
3. 관측 vs 모델 곡선 플롯 → 독자와 적합 품질 확인 (초반 급락·후반 꼬리가 맞는지).
4. `baseline` 계산 → 기능의 일 신규 유저 수·D1 리텐션을 물어 최종 DAU 기여 산출(실습 3의
   퀴즈 표와 같은 꼴로 정리하면 좋다). 결과를 말할 때 기준 기간("1년 시점의 기대 DAU")을 함께 붙인다.

### 5. 결과 해석

- `b`가 0에 가까울수록(완만) 상수가 크다 = 신규 1명의 장기 DAU 가치가 크다.
- 공식은 "신규 유입을 늘리는" 액션과 "D1을 올리는" 액션과 "커브를 완만하게 하는" 액션의
  기대 효과를 각각 분리해 계산할 수 있게 해 준다 — 독자의 논의 중인 액션에 대입해 준다.
  책 7절의 레버 환산(D1 1%p ≈ 일 신규 몇 명)을 독자 숫자로 다시 계산해 보여주면 좋다.
- 이 값은 **기능 DAU**다. 서비스 전체 DAU 순증은 다른 기능에서 옮겨 온 유저 때문에 더 작을 수
  있으니, 순증이 궁금하면 실험군/대조군 비교를 권한다.
- D1~D28 관측으로 365일을 외삽한 값임을 항상 병기한다.

## 함정

- `curve_fit`에 `p0` 초기값을 하드코딩하지 말 것 — 기본값으로 충분히 수렴한다.
- power law는 초기 급락 후 완만한 감소 형태에 맞는 모델이다. 요일 효과로 리텐션이 오르내리면
  주 단위 평균으로 스무딩 후 적합한다.
- `x^b`의 누적합은 등비급수와 달리 수렴값이 없다 — 기간을 늘리면 상수가 계속 커진다. 상수를
  공유할 때는 "1년 시점" 같은 기준 기간을 반드시 함께 말한다.
- 상수는 서비스마다 다르다(책 본문 예시 63, 실습 데이터 약 41). 남의 상수를 가져다 쓰지 말고
  우리 서비스 커브로 구한다.
- `b`는 신규 기능 자체의 짧은 데이터가 아니라 서비스 전체(또는 가장 유사한 기능) 신규 유저
  커브에서 구한다. 기능 쪽에서는 신규 유저 수·D1만 쓰되, 오픈 효과·배포율 영향이 가라앉은
  안정화 구간의 값을 쓴다.
- 오래 운영된 기능은 이미 쌓인 유저가 있어 신규·D1만으로 설명되지 않는다 — 추정치와 실측 DAU의
  차이를 `기존 유저 계수`로 더해 쓴다.
- 공식이 주는 것은 기능 DAU이지 서비스 DAU 순증이 아니다(카니발라이제이션). 순증은 실험으로 잰다.
- 장기 코호트가 있다면 외삽값을 실측과 대조해 보정한다. 출시 후 실측 DAU와 추정치가 크게
  어긋나면 커브를 다시 적합한다.

## 학습 가이드

### 핵심 개념 — 이 챕터를 마치면 설명할 수 있어야 하는 것

- **리텐션 커브** — 코호트의 D+n 잔존율을 n에 대해 그린 곡선. DAU는 과거 코호트들의 커브 합.
- **power law 감쇠** — `y = a·x^b` (b<0). 지수 감쇠와 달리 꼬리가 두꺼워 앱 리텐션에 잘 맞는다.
- **모양 계수 `b`** — 커브가 얼마나 빨리 꺾이는지. `a`(시작점≈D1)와 분리된 "습관화" 지표.
- **상수로 접기** — `1 + Σ x^b`. 커브 전체를 "신규 1명이 1년간 만드는 활동일수" 배수 하나로 요약.
- **외삽의 한계** — 28일 관측으로 365일을 추정하는 것이므로 모델 가정이 곧 리스크.

### 개념 체크

1. `b`가 -0.3인 서비스와 -0.6인 서비스가 있다. 장기 DAU 배수(상수)가 더 큰 쪽은 어디인가?
   이유도 함께 설명해 보라.
   - 힌트: -0.3. `x^b`는 b가 0에 가까울수록 천천히 감소 → 누적합이 커진다.
2. 최종 공식은 "신규 유저 수 × D1 리텐션 × 상수"로 D1 리텐션과 상수를 굳이 분리해 두었다.
   하나로 합치지 않고 분리한 이유는?
   - 힌트: `a`(=D1)는 온보딩 개선으로, 커브 모양(`b`)은 습관 형성 기능으로 움직인다 — 레버가
     다르고, `b`는 서비스 전체 커브에서 한 번 구해 상수로 재사용한다.
3. "오늘 DAU = 신규 유저 수 × 리텐션 커브의 누적합"이 되는 이유를 코호트로 풀어 설명해 보라.
   이 식이 성립하려면 어떤 가정이 필요한가?
   - 힌트: 오늘 DAU = 오늘 신규 + 어제 신규 중 잔존(D1) + 그제 신규 중 잔존(D2) + …. 일별 신규
     유저 수가 일정해야 공통인수로 묶인다.
4. Carrying Capacity 공식은 기능 A의 DAU를 7,200으로 계산했지만 실제는 2만이 넘었다. 어디서
   과소평가가 생겼나?
   - 힌트: 일간 리텐션이 매일 일정하다는 등비급수(지수 감쇠) 가정 — 30일이면 잔존이 0 근처로
     붕괴한다. 실제 커브는 초반 급락 후 완만해지는 멱함수 꼴이라 오래된 코호트의 잔존이 쌓인다.
5. D1~D28 관측으로 구한 `b`로 1년치 상수를 계산했다. 이 상수를 다른 팀에 공유할 때 반드시
   함께 말해야 하는 것 두 가지와 그 이유는?
   - 힌트: (1) 기준 기간 — `x^b` 누적합은 수렴하지 않아 기간을 늘리면 상수가 커진다("1년 시점의
     기대 DAU"). (2) 우리 서비스 커브로 구한 값이라는 점 — 서비스마다 다르다(본문 63 vs 실습 41),
     그리고 28일 관측을 365일로 외삽한 값이다.
